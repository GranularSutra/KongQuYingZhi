#### V2架构更新记录
普通问答：如果不需要创造力，那么普通的统计模式已经够用了。
类比迁移：普通学科类比，语料的“结构迁移”足够产生“类比、灵感”，没必要用“波动图论·空间曲线”，那个算力要求还是太高了。
加快落地：V1版本工作量初期尚可，已经验证1GB文本的处理速度（FP64浮点坐标+曲线编码，约15分钟），单后期工作量就太大了。
细化工程：具体细化了生成步骤、上下文理解步骤、数据库结构、语法结构
简化原理：简化了TF的逻辑理解、发展历程、替代方案
泛化加强：文本匹配能力获得质变提升，根由是，把部分“未来计划”变成了“当前计划”
当前目标：单句生成，耗时50ms，语料压缩比>100。
版本对比：V2并不是比V1更好，而是更侧重加速落地。小修小补就不罗列了。V2已经彻底舍弃了对TF本体的“形式模仿”，不执着“拟合”。

#### TF为什么是‘矩阵’
‘图像时代’选择了矩阵计算，‘深度学习’继承了这个选择，‘语言模型’继续继承 → 一脉相承


#### TF训练推理蒸馏区分
训练权重=训练时，模型从语料里学到的固定参数，用于取代原始语料，作为模型的知识载体；对比原料，高压缩比（超百倍）、高泛化、低引用；实质是“词汇表对语料的映射记录”与“语义拟合”；训练结束不再改变，所有推理请求共用。
推理权重=推理时，动态计算的注意力分布，它是模型在推理时根据当前输入（上下文）计算出的权重值；告诉你在当前语境下应该关注哪些位置或哪些词；此时尚未出token
蒸馏传递=将要输出的token输出结果，其备选列表，每项映射到词汇表的概率。（比如“猫：80%，狗：15%，兔子：5%”）。对智力不构成正面加成。


#### TF量化
首先，LLM≈函数图像
量化不保留知识，因为权重本就只有拟合的“函数图像”，不保留作图时的“密集点”。
量化N倍=降低屏幕分辨率 → 体积缩小N倍 → 误差被维数分摊 → ‘大模型量化’实测确实优于‘小模型保全’，取舍后默认Q4A8
原始4K硬件（看1K图锐利） → 切换显示1080P分辨率（看1K图模糊） → 四个像素间存在漏光，不是封闭 → 光学干扰被放大 → （模糊并不是采样精度降低造成的） → 糊（视觉比逻辑精度高）

#### TF的智能涌现的逻辑图
- 涌现：模型没有真正“理解”任何东西，它只是在语料里找最像的模板来套
- 基础：2018~2022
	- 时代特点：TF发表于2018年，2022年企业硬件已经足够万亿参数。
	- 本质：“词级”统计机器，它只学词与词之间的共现概率，学不到句子级、段落级、文章级的结构，也没有学“句子之间的各类关系”。
	- 特点：回复短，猜词堆砌，百字算豪放，千字属做梦，逻辑≈0，时空日迷茫，因果不存在。
	- 案例：Anthropic·claude，2023年初期免费，当时的能力边界为“你给关键词，让它生成相关信息，分条罗列，类似无广告的搜索引擎”
	- 含义：TF的真实能力天花板，再2023年之前已经确认了
- 拐杖：2022年开始
	- 本质：“用符号系统的拐杖，去强行矫正一个统计系统的缺陷，还不敢承认”
	- 监督反馈（RLHF，人类纠偏）
	- 语法解析、多头注意力、时间排序（过于粗糙）、因果链（句级关系、段级关系）、思维链、数据库查表、系统提示词、格式化输出、工具调用、实体识别、实用思维链固化（≈硬编码函数，但效果差一些）、智能体（≈思维链固化，但更低效）
	- 其他若干，各场各秀，唯独不做3D数学
	- 注重语料：成倍降低参数量，成倍提高原始语料体谅 → 更多的模板 → 更好的表现
	- 逐步加入编程能力
	- 拐点代表作：Chinchilla
	- 争议1：2023年各类工具突破了TF能力边界，拐杖能不能算作本体的一部分？因为拐杖的原理是可移植的。
	- 争议2：即使它们不承认，但它们就是把“前后句之间的关系”，单独做了显式统计。这直接解释了，“为什么模型不看字面意思，回复错误的理解”
	- 争议3：语言的模糊性、例外、隐喻、新词、语境变化，现在同样搞不定，因为语义本就因人因事而定。
- 依然存在的问题（以Dr.D为准，2026年8月）
	- 精神分裂：定义明确禁止任何“开放式厨房”，RPG中出现“开放式厨房(虽然是玻璃隔断的)” → 以词为单位生成内容，导致的“精神分裂”
	- 缺失3D认知
	- 认知错乱（印象深刻，2025年还是2024来着）
		- 用户：用Dr.D的API，本地sillytavern进行RPG，内容出现"都市写实RPG，出现孕妇怀孕3年"，而这个世界观不涉及任何超自然。
		- 用户：气疯了，开浏览器，进Dr.D官网，新对话，直接问“为什么...现实中明明是1年以内”
		- AI回复大意：用户认知出了问题，超长孕期这个现象并不罕见，用户的认知是偏见，不是物理事实。
		- 用户：你联网查！
		- AI回复大意：确实没找到，但并不能证明...，这是一个误解...需要我帮你改正么...
		- 2026年的情况：此类事实问题已经极少出现，但逻辑矛盾从未减少。只有重新生成才能盖过去，和AI争论没用。且早就RPG出戏了。且你争论三轮，它就会智商错乱，后面全废。堆一句自洽自证的设定，胜过百句争论。
	- 时序错乱
	- NPC上帝视角，即缺失“认知隔离机制”
	- 缺失灵感机制
	- 对于输入内容，专擅引申、歪曲，而非专注文本字面意思。
	- 总结：它甚至无法胜任RPG和学科问答
- 复杂度来源：TF打散词序，训练和推理都是，推理依赖位置编码。
- LLM训练≈刷题
- 小结
	- 矩阵训练的本质是“猜词”，不是“理解”
	- 位置编码(上下文输入)只是粗糙的“拐杖”，救不了词序（训练时按句切词，无序，概率拟合‘出现下一个词’而非整句）
	- “智能”的提升，全靠后期加装的拐杖
	- 真正有价值的，是‘因果链’和‘逻辑结构’，不是具体句子或者段落（“一句话一句话训练”，天然缺失句子间的因果关系）。
		- “小红打了小明”这句话本身毫无意义，有意义的是它在上下文里的因果链：“被侮辱 → 反击”、“被火烧 → 疼/死”。这些因果链种类有限，根本不需要矩阵去“涌现”。
		- 完全可以做成枚举库，并标注出现频率（非必要）。
		- ‘因果’默认两级，一般≤3级。
		- 有限‘因果/逻辑’嵌套/承接，即无限。

#### AI训练

- 架构名称：空曲映智，“Spatial Curve Hold Intelligence”，简称SCHI
- 核心主张
	- 语言智能的本质是结构（语法、因果、逻辑）的识别与复用，而不是词频的统计拟合。可以用硬编码的规则、模板、层级化数据库和轻量级统计，完全替代TF的暴力矩阵运算。
	- 认知结构是不变的（因果、时空、逻辑），知识是相对稳定的（建国年份、物理定律），而表达方式是在不断变化的（新词、新梗、流行语），把这三层分开处理，每一层的更新成本就变得极低。数据库分块应运而生。
- 解决的问题
	- 训练成本高（<0.001倍）、迭代速度慢（>100倍，训练成本导致的可修改性不同）、硬件成本高（0.3~0.1倍；显存/内存虽同是ram，但价格不一样，可扩展性不一样。）
	- 提高上限（认知隔离、遗忘、传播）、补足缺失（空间）、动态时间（默认按时间轴排序；层级管理和定位；RPG的新信息和新事件，按照实际事发时间，插入合适的时间节点，不明确则标记‘估算’）
- 搁置的：编程、多国语、图片、视频、法律。原理公开，过于直白，能力足够，迁移可行，实现交给旁人。首要完成中文、TSEn的文字交流
	- 你问对不对，可以说，你问合不合法，这个就模糊了。
	- 理论上法律不能禁止个体对事物的发表看法，但现实不是这么进行的，名目有很多，每一条都能合法定罪。
	- 数据库分块，我没有计划搞政治、法律之类的推理，你得自己找自己装，理论上能跑。


- 获取原始语料：选择开源语料库
	- 确保输入一致，便于对比
- 清洗语料：去除噪声（HTML标签、乱码、重复内容）、规范化（统一编码、处理特殊字符）
	- 可视语料质量省略
- 词表构建：基于该语料构建词表（可使用ChatLM的tokenizer方案）
- 词频分割：每条语料，按规则对语料进行词频分割，得到词序列。
- 词性标签表：
	- 名词、动词、形容词等
	- 角色标签表：施动者、承受者、传递物等
	- 分类标签表：人名、地名、物名、抽象概念、化学式等
	- 因果类型表：触发、传递、变化、状态等
- 词表分类标签：参考维基百科，约400

- 词表规模：本地词表<6万词，用2字节（16位）索引；核心词表104万词（20位）足够覆盖单语言核心概念；多国语交给“翻译引擎”映射
	- 理想情况：TSEn作为内部语，其他直接映射翻译。
	- 实际情况：先搞中文看看效果
	- 数据结构：初期采用“分开存储”，词表只负责词ID映射，标签（词性、实体类型等）作为独立映射层。等需求明确了，再决定是否合并为3字节打包。再慢也比TF快

- 泛化机制
	- 使用场景
		- 精确对话（法律、判例、行政文书），不做泛化，改数据库硬存
		- 通用对话（日常聊天），部分泛化
		- 大规模知识库（百科），专有词保留，其余泛化
		- 纯结构推理（因果分析），极致泛化，超高压缩比
		
- 猜词机制
	- 举例1：‘傻比’，看到‘傻’这个字，你就能猜到大概率是骂人的词汇；‘贱骨头’，‘贱’字同理；上下文+猜，也算是兜底之一；这在共情用户情绪时，是非常必要的检测手段
	- 举例2
		- 了雨下昨天发布了新歌 → 主语位置 → 名词 → 人名/艺名/机构
		- 昨天发布了新歌了雨下 → 新歌了雨下 → 同位语，名词，歌名
		- 了雨下 → 什么都没提示，字面义不明确 → 新词，等待下次出现再打标
		
		
- 上下文理解
	- 举例1：“他的心是石头做的”，逻辑拆解“a=xxx是xxx做的；b=心；c=石头 → 石≈心” → 匹配成功（比如铁石心肠、冷血、没有同理心、缺乏共情、冷酷无情）


- 统计概率：双层统计系统
	- 第一层：标签层（结构层）
		- 统计“标签组合”的频次，而不是具体词的频次
		- 例如：（人名代词→赠送类动词→家庭称呼→水果类名词）这个标签组合出现了多少次
		- 这一层负责结构的准确性——确保生成的句子在语法和逻辑上是正确的
	- 第二层：词频层（填充层）
		- 在每个标签内部，记录具体词的频次
		- 例如：“人名代词”这个标签下，“小红”出现了120次，“小明”出现了80次，“老王”出现了15次
		- 这一层负责填充的合理性，确保选出来的词在统计上是合理的。对于非重要事实，则泛化名称类型
	- 生成时的工作流程
		- 选结构：从标签层选一个标签组合（例如“人名代词→赠送类动词→家庭称呼→水果类名词”）
		- 填词：按照逻辑函数、打分表、备选词

- 通用枚举库枚
	- 放心大胆，必然<1000万条
	- 人类认知 ≈ 因果模板+逻辑模板+语法模板+语义角色+世界知识框架
	- 其中，“高抽象层”的“枚举”，直觉上，<1000条
	- 枚举库分级：炽（顶级抽象）；热（常用+普通抽象）；温（不常见，作备用，按需加载）（比如“最简原始朴素法”<100条，是划边界，不涉及包容或者妥协）；冷（领域隔离，未加载，在ssd或hdd）；冻（不加载/实例少）
	- 典型的数据库归档：比如各国法律原文、判例，不会进入通用枚举库，默认不加载（实际云服务商部署时，冷/冻都是专用存储服务器，作为公用）


- 可选优化
	- 表达引擎：每个语言不一样，用于把思考结果，润色后输出给用户；中英优先
	- 逻辑语言：用“简化英语”构建中间按语言，从而成倍提升性能、降低歧义、提高命中率
		- 语法拆分：根据句法结构，标记每个句子的“主语、谓语、宾语、状语”
			- 预计可省略掉用于“涌现语法”的参数量

	- 专有语料数据库压缩举例
		- 核心前提：目的是原样保持，否则大可不必如此麻烦。
		- 通用全局词汇表A，采用FP16或者混合精度或者级联整数分区索引；通用句法集C（按需扩展，默认C=8bit≈256例足够，‘语法工具’衍生无限）
		- 该语料库的对外标签：用A打标，方便全局检索
			- 更强的泛化（可选）：每个标签存为数组r，r[0]=精确，其他=模糊匹配；也可固化，比如精确1，模糊3，其他2；数据排布优化可以自定，但表面逻辑当如此
		- 建立映射：遍历，做出本地词汇表B，如果“B的词表<6.5万”，则用B，好处是更省带宽和体积；默认用A；映射关系作为D，全局检索时使用
		- 合并总集：按需决定，是否临时将B挂到全局，便于全局检索。默认不做。
		- 普通压缩：以词表，结合句法C，使用特定形式压缩
			- 每个句子，用“词表映射”替换，适合短句文、快速压缩。
			- 一个汉字按‘UTF-8’编码，通常占3字节；假设1000万字中文小说，词表2万词；2字/词，
			- 则索引大小=log2(2万)≈2字节，则1÷2÷(3/2)≈0.33倍，即压缩后体积≈0.33倍
		- 句法高压（可选）：基于普通压缩，每个句子，用“语法工具+句法参数+词汇数组”替换，仅适合长句文。（大部分情况下，成倍提高算力消耗，文法转义将碾压作者）
		- 结构高压（可选）：基于普通压缩，长句用短句指针组合每个句子，仅适合长句文。
		- 二次压缩（可选）：Gzip/Zstd加壳，进一步压缩。该状态适合冷数据或存储空间受限场景。

#### ‘空曲映智’对比‘TF’
- 原理可理解性
	- TF：江苏二本工科，完全看不懂“为什么经过xx操作会得到xx结果”；（字面意思，本人就是这么个经验，1整个月的高强度学习过去，啥都看不懂，也复现失败，字面意义的“demo复现失败”。）
	- 空曲架构：承认文字AI就是摆弄字符，只不过需要符合现实的文字游戏规则；最难的也就高中物理习题课水平；比“c++模板库”简单；（字面意思，本人就是这么认为的）
- 输入表示层
	- TF：词嵌入向量 + 位置编码，把词映射成高维连续向量。
	- 空曲架构：词表映射、语法元素识别
- 上下文建模层
	- TF：多头自注意力，计算当前词与上下文中所有词的相关性权重，动态生成加权表示。
	- 空曲架构：因果、逻辑、结构、实体识别、统计，并缓存；近距离语句内，词打分；附近句子目的识别，待生成内容目的识别；生成关键词用于检索
- 知识存储层
	- TF：权重矩阵，通过反向传播和梯度下降将语料统计信息压缩成抽象的、不可解释的数值。
	- 数据库、工具库、词表、统计、缓存识别结果、缓存规划
- 推理层
	- TF：输入上下文 → 矩阵乘法 → 输出概率分布 → 采样下一个“词”。
	- 空曲架构：以“句子”为单位输出，工具函数负责理解、校验、检索、选择、随机、生成。比如内化的临时TD逻辑图即“因果函数建模”
- 训练层
	- TF：反向传播 + 梯度下降，对权重矩阵进行多次迭代优化，需要大量GPU算力和数周至数月时间。
	- 空曲架构：抽象句间关系；抽象句内元素、关系；各类表达模板、工具、数据库、枚举库
- 新因果/逻辑
	- TF：未知，尚无公开的直白证明，可能是映射到已有统计模式。
	- 空曲架构：标记为“新类型”并提取；拆解为新标签组合，存入临时因果链库，并标记核验打分；可以被存储到硬盘上，白盒没有私藏。
- 对拐杖的态度
	- 各厂：“架构创新”“模型能力”
	- 空曲：是拐杖，是工具包，是数据库，这些是必要的矫正/发散措施。
