#### 解析举例
```
句子：因为饿了，张三狠狠地吃了那个红苹果
	↓
最外层主谓宾：张三 → 吃 → 苹果
	↓
标记1：张三（施动者）、吃（动作）、苹果（受动者）
	↓
从句标记：因为饿了（原因状语，嵌套在主句前）
	↓
修饰标记：狠狠地（方式）、那个红（修饰苹果）
	↓
最终标记结果：最外层[张三→吃→苹果] + 原因从句[饿] + 方式[狠] + 修饰[红]
```

#### 理解上下文
1. 整个过程，与游戏引擎中的“怪物逻辑”，一个（树）a管逻辑执行，一个（黑板）b管数据记录。
2. 正因如此，它可以进行代码级的追踪和结算，有助于维护因果。第N句话，第N+16句话，同一个实体，对应的是同一个变量，如果无法确定，则加标记。
3. 全部上下文缓存备用（结算结果）
4. 全部名词列表备查（临时数据库）
5. 用户可通过楼层计数，来明文传达焦点位置，比如“第xx楼的xxxx”
6. 并无显式的上下文窗口限制。
7. 歧义处理：对于新输入，比如“他开心的笑了”，如果AI无法识别，会直接提示，比如output=“歧义处为...”；可开关，关闭则模糊和随机处理；默认关闭
8. 函数识别：对于明显的新逻辑链/设定法则，识别后会直接提取为“逻辑函数”，且区分归属哪个实体/全局，并记录最后一次更新的楼层。。模糊则设为全局。典型标记即因果结构、步骤结构、推理结构。默认关闭
9. 精确开关：对用户新输入的内容，默认每个字都是精准的，不进行任何错字矫正。默认关闭
10.待解决：如何做好关系、名词的层级存储、嵌套，暂定不解决。

#### 关于编程语法
- 怀疑：AI的确能自动学习、自动建模，但其精度存疑。业界的编程AI，是迭代两年时间才侃侃可用，大概率是加拐杖了。
- 猜测的步骤
	- 语法硬编码 → 把编程语言的语法规则写死，不让模型自己“猜”
	- 逐步检查 → 每一步都做语法检查，不符合的直接拒绝输出
	- 结构化输出模板 → 强制让模型输出符合特定格式的代码
	- 代码组装 → 从不同地方抄代码片段，组合起来

#### AI训练

- 架构名称：空曲映智，“Spatial Curve Hold Intelligence”
- 核心主张
	- 语言智能的本质是结构（语法、因果、逻辑）的识别与复用，而不是词频的统计拟合。可以用硬编码的规则、模板、层级化数据库和轻量级统计，完全替代TF的暴力矩阵运算。
	- 认知结构是不变的（因果、时空、逻辑），知识是相对稳定的（建国年份、物理定律），而表达方式是在不断变化的（新词、新梗、流行语），把这三层分开处理，每一层的更新成本就变得极低。数据库分块应运而生。
- 解决的问题
	- 训练成本高（<0.001倍）、迭代速度慢（>100倍，训练成本导致的可修改性不同）、硬件成本高（0.3~0.1倍；显存/内存虽同是ram，但价格不一样，可扩展性不一样。）
	- 提高上限（认知隔离、遗忘、传播）、补足缺失（空间）、动态时间（默认按时间轴排序；层级管理和定位；RPG的新信息和新事件，按照实际事发时间，插入合适的时间节点，不明确则标记‘估算’）
- 搁置的：编程、多国语、图片、视频、法律。原理公开，过于直白，能力足够，迁移可行，实现交给旁人。首要完成中文、TSEn的文字交流

	- 数据库分块，我没有计划搞政治、法律之类的推理，你得自己找自己装，理论上能跑。

- 泛化机制
	- 使用场景
		- 精确对话（法律、判例、行政文书），不做泛化，改数据库硬存
		- 通用对话（日常聊天），部分泛化
		- 大规模知识库（百科），专有词保留，其余泛化
		- 纯结构推理（因果分析），极致泛化，超高压缩比

		
- 猜词机制
	- 举例1：‘傻比’，看到‘傻’这个字，你就能猜到大概率是骂人的词汇；‘贱骨头’，‘贱’字同理；上下文+猜，也算是兜底之一；这在共情用户情绪时，是非常必要的检测手段
	- 举例2
		- 了雨下昨天发布了新歌 → 主语位置 → 名词 → 人名/艺名/机构
		- 昨天发布了新歌了雨下 → 新歌了雨下 → 同位语，名词，歌名
		- 了雨下 → 什么都没提示，字面义不明确 → 新词，等待下次出现再打标

		
- 上下文理解
	- 举例1：“他的心是石头做的”，逻辑拆解“a=xxx是xxx做的；b=心；c=石头 → 石≈心” → 匹配成功（比如铁石心肠、冷血、没有同理心、缺乏共情、冷酷无情）


- 统计概率：双层统计系统，适用于句法
	- 第一层：标签层（结构层）
		- 统计“标签组合”的频次，而不是具体词的频次
		- 例如：（人名代词→赠送类动词→家庭称呼→水果类名词）这个标签组合出现了多少次
		- 这一层负责结构的准确性——确保生成的句子在语法和逻辑上是正确的
	- 第二层：词频层（填充层）
		- 在每个标签内部，记录具体词的频次
		- 例如：“人名代词”这个标签下，“小红”出现了120次，“小明”出现了80次，“老王”出现了15次
		- 这一层负责填充的合理性，确保选出来的词在统计上是合理的。对于非重要事实，则泛化名称类型
	- 生成时的工作流程
		- 选结构：从标签层选一个标签组合（例如“人名代词→赠送类动词→家庭称呼→水果类名词”）
		- 填词：按照逻辑函数、打分表、备选词


- 训练内容（泛化成标配）
	- 综述：词法、句法、段法、文法，作为枚举备用，包含机器活、脑力活、体力活，一部分是一次性工作。
	- 句法：
		- 泛化的“近观积木”
		- 各类句式、表意结构、句法转化、实体识别、语义角色
	- 段法：
		- 泛化的“中观骨架”
		- 一个观点，被哪些小论点串联起来，即关键词节点以及节点之间的关系；每个小论点，都可能有许多同类、相似的，包括结构、关系的相似

		- 枚举库（因果、逻辑、句式、少量语料） → 文本异常高压缩比>>100 → “TB语料压缩成枚举库，体积/检索压力骤减，反而让句子模板库/原味语料库，可以放心加倍。”
			- 举例：“xx，a家xx着火了xx，xx消防队xx救火xx，xx”提取为“[杂1]→着火→[杂2]→消防队→[杂3]→救火→[杂4]”
	- 信息标记
		- “掩码”：可标记信息缺失。比如“小红背后偷袭敲打小明脑壳”，此处小明不知道是小红。即在小明的本地历史记录里面，需要对这条记录的主语“小红”，根据语法元素，做掩码标记。
		- 主要用于建立和维护NPC的本地认知库，降低重复语料
		- 信源信度标签（可选）
		- 时间戳（可选）
	- 语法元素：主语，谓语，宾语，定语，状语，补语，同位语，独立语；其他句法分类、语法分类
		特例：请他来/赶他走 → 祈使句，“let sb do sth”，其中let是‘使令标记’，“sb do sth”是内容，sth省略可以扩大范围或者强调动作
		特例：推开门，走出去 → 连续动作，“do sth”的连续组合
		举例：我没去过首都北京 → 首都北京时同位语句式
	- 专有语料数据库压缩举例
		- 核心前提：目的是原样保持，否则大可不必如此麻烦。
		- 通用全局词汇表A，采用FP16或者混合精度或者级联整数分区索引；通用句法集C（按需扩展，默认C=8bit≈256例足够，‘语法工具’衍生无限）
		- 该语料库的对外标签：用A打标，方便全局检索
			- 更强的泛化（可选）：每个标签存为数组r，r[0]=精确，其他=模糊匹配；也可固化，比如精确1，模糊3，其他2；数据排布优化可以自定，但表面逻辑当如此
		- 建立映射：遍历，做出本地词汇表B，如果“B的词表<6.5万”，则用B，好处是更省带宽和体积；默认用A；映射关系作为D，全局检索时使用
		- 合并总集：按需决定，是否临时将B挂到全局，便于全局检索。默认不做。
		- 普通压缩：以词表，结合句法C，使用特定形式压缩
			- 每个句子，用“词表映射”替换，适合短句文、快速压缩。
			- 一个汉字按‘UTF-8’编码，通常占3字节；假设1000万字中文小说，词表2万词；2字/词，
			- 则索引大小=log2(2万)≈2字节，则1÷2÷(3/2)≈0.33倍，即压缩后体积≈0.33倍
		- 句法高压（可选）：基于普通压缩，每个句子，用“语法工具+句法参数+词汇数组”替换，仅适合长句文。（大部分情况下，成倍提高算力消耗，文法转义将碾压作者）
		- 结构高压（可选）：基于普通压缩，长句用短句指针组合每个句子，仅适合长句文。
		- 二次压缩（可选）：Gzip/Zstd加壳，进一步压缩。该状态适合冷数据或存储空间受限场景。
		- 特征：高压缩（0.3~0.01）、结构化存储、检索无需解压（前提不加壳）、内存占用小、泛化且跨语言且高速（标签+整数检索）、支持多标签协同检索。
		- 效果：RAG用户做梦都求不来的待遇。

- 推理引擎
	- 基础条件
		- 丰富模板：大量专用泛化模板，“短语级，整句级，段落级，文章级，因果链，逻辑链（因果、转折、条件、并列等）”，被代码固化为工具函数/枚举。
		- 核心句型：比如300种
		- 逻辑关系：比如20种
		- 语义角色组合：比如100种常见组合
		- 完整管道：各类工具函数，覆盖理解、分析、校验、选择、检索、随机、扰动、生成等一系列
	- 输入解析：接收用户输入，进行词频分割，提取当前上下文窗口（固定窗口或动态窗口）。
	- 长文生成流程：话题 → 检索 → 定论 → 分步 → 分段 → 细化
	- 段内生成流程：理解 → 打分 → 定论 → 查表 → 替换 → 拼接
		- 上下文分析（一次，缓存）
		- 确定当前句子意图（基于缓存）
		- 检索对应的标签/关键词（3-5个）
		- 匹配语法模板（从模板库取）
		- 填充槽位（从检索结果取词）
		- 输出句子。以句子为单位 → “省步骤”+“句级思维一致”
	- 语法泛化
		- 对前文采样，得到语法规则下的元素确认。
		- 表达引擎核心：常见句式枚举+语法嵌套+文法案例+对答案例+词汇表+词性；不同语言不同引擎
		- 语法元素：“主语+谓语+宾语+状语”即。
		- 步骤：先采样识别，再定语法句式，后填元素。
	- 循环生成：重复上述步骤，直到生成完整回复或达到停止条件。
	- 汉古词法：短语 → 词组 → 拆字，识别并解决古文/半古的短小精悍，比如，“汝何人”“先折，后拆，再断，你是真毒”


- 监督反馈（可选）
	- 错误检测：记录生成结果中的明显错误（如语法错误、逻辑矛盾、不符合设定）。
	- 权重调整：对错误路径涉及的统计指针进行降权（如降低10%-20%），然后重新测试。
	- 人工审核迭代：对高风险或不确定的生成结果进行人工审核，调整对应曲线的概率分布。

#### ‘空曲映智’对比‘TF’
- 原理可理解性
	- TF：江苏二本工科，完全看不懂“为什么经过xx操作会得到xx结果”；（字面意思，本人就是这么个经验，1整个月的高强度学习过去，啥都看不懂，也复现失败，字面意义的“demo复现失败”。）
	- 空曲架构：承认文字AI就是摆弄字符，只不过需要符合现实的文字游戏规则；最难的也就高中物理习题课水平；比“c++模板库”简单；（字面意思，本人就是这么认为的）
- 输入表示层
	- TF：词嵌入向量 + 位置编码，把词映射成高维连续向量。
	- 空曲架构：词表映射、语法元素识别
- 上下文建模层
	- TF：多头自注意力，计算当前词与上下文中所有词的相关性权重，动态生成加权表示。
	- 空曲架构：因果、逻辑、结构、实体识别、统计，并缓存；近距离语句内，词打分；附近句子目的识别，待生成内容目的识别；生成关键词用于检索
- 知识存储层
	- TF：权重矩阵，通过反向传播和梯度下降将语料统计信息压缩成抽象的、不可解释的数值。
	- 数据库、工具库、词表、统计、缓存识别结果、缓存规划
- 推理层
	- TF：输入上下文 → 矩阵乘法 → 输出概率分布 → 采样下一个“词”。
	- 空曲架构：以“句子”为单位输出，工具函数负责理解、校验、检索、选择、随机、生成。比如内化的临时TD逻辑图即“因果函数建模”
- 训练层
	- TF：反向传播 + 梯度下降，对权重矩阵进行多次迭代优化，需要大量GPU算力和数周至数月时间。
	- 空曲架构：抽象句间关系；抽象句内元素、关系；各类表达模板、工具、数据库、枚举库
- 新因果/逻辑
	- TF：未知，尚无公开的直白证明，可能是映射到已有统计模式。
	- 空曲架构：标记为“新类型”并提取；拆解为新标签组合，存入临时因果链库，并标记核验打分；可以被存储到硬盘上，白盒没有私藏。
- 对拐杖的态度
	- 各厂：“架构创新”“模型能力”
	- 空曲：是拐杖，是工具包，是数据库，这些是必要的矫正/发散措施。
- 空曲架构独有
	- 认知引擎、记忆引擎、灵感引擎、物理引擎、时空引擎、地理引擎、传播引擎、过程隔离、主从模式
	- 数据库高压、无解压检索、极致白盒
	- 极致训练速度、推理速度、低硬件要求
